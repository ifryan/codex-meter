## 1. 已确认的目标

- 保留原生 macOS 14+ 应用、刘海及无刘海屏幕的紧凑展示。
- 同时支持订阅额度、Coding Plan、API 余额、Token 与费用；按来源声明实际能力。
- 提供广泛的内置适配器，社区可通过 PR 增加来源。
- 支持同一来源的多个命名账户、API Key，以及独立的国内／国际区域连接。
- 支持本机 CLI／应用登录态、API Key、网页登录／Cookie；用户选择添加后启用采集。
- 自定义来源只提供 HTTP 查询表单和 JSON 字段映射，不提供脚本执行或外部插件运行时。
- 用户选择最多 3 个来源／账户常驻，选择各项的主指标，展开查看全部已启用连接。
- 增加独立轻量统计窗口，展示今天／7 天／30 天的用量、费用与趋势。
- 数据来自服务商接口、本地日志或已有工具；本项目不建设请求代理或模型路由。
- 优先使用不消耗推理额度的查询方式；付费探测由用户单独开启。

## 2. 当前基线与改造边界

2026-10-27 只读核对结果：

- `Domain.swift` 的 `MeterAgent` 固定 Codex、Claude、GLM 三项，常驻值主要围绕百分比和 5 小时／周窗口。
- `AppDelegate.swift` 显式持有三套 client、loader、刷新和通知接线。
- `NotchUI.swift` 仍以三项来源作为展示基线，不能直接承载任意数量账户。
- `UsageLoader` 已具备独立刷新、取消、去重、旧值保留和旧请求结果隔离，可继续复用。
- GLM 配置与钥匙串存储是单一来源专用实现，需要逐步迁移为账户级配置。
- 仓库已有 README、中英文文档、隐私说明、安全策略、贡献说明、许可证、Issue／PR 模板和 CI；在现有基础上更新。
- 工作区已有大量未提交修改及未跟踪源码。它们构成本次迁移的实际基线，不重置、不覆盖；本计划不提交或推送代码。

## 3. 核心设计

采用“来源定义 → 账户实例 → 获取策略 → 标准化数据 → 展示／历史”的结构。

| 层 | 责任 |
| --- | --- |
| 来源注册表 | 稳定 ID、名称、区域、认证方式、指标能力、默认刷新策略和配置字段 |
| 账户实例 | 唯一账户 ID、用户命名、启用状态、凭据引用、常驻状态与主指标 |
| 获取策略 | HTTP、CLI、OAuth、应用登录态、Cookie、本地日志和已有工具连接 |
| 标准化数据 | 任意周期窗口、余额、Token、服务商返回费用、估算费用、单位、身份、更新时间及覆盖范围 |
| 运行状态 | 加载、未配置、需要登录、失败、旧数据、取消及账户变更隔离 |
| 展示与历史 | 刘海速览、全部来源详情、连接设置、用量统计及本地存储 |

费用与余额使用适合货币的数值表示，保留币种。未知值保持未知；未知费用不计作免费。不同币种、不同时间范围、不同统计口径不直接相加。

额度来源与工具日志分开：多个工具共享一个供应商账户时，账户额度只显示一次；工具维度另外统计其日志用量。日志无法可靠归属账户时显示“未归属”，不猜测身份。

## 4. 执行阶段

### P0：记录基线与建立支持矩阵

工作：

- 记录现有工作区修改、配置格式、排序规则、通知行为与专用凭据条目。
- 建立适配器矩阵：来源／区域、额度、余额、Token、费用、认证要求、接口依据、实现状态和验证状态。
- 实施时固定参考项目的源码版本，重新核对接口契约，记录实际引用代码及来源。
- 确定旧配置迁移格式与可恢复方式；密钥不进入配置备份。

交付：支持矩阵、迁移说明、任务拆分。

完成条件：清楚区分现有能力、待迁移能力与新增能力；当前未提交工作有明确保护边界。

### P1：通用架构与现有三家迁移

工作：

- 建立来源 ID、账户 ID、能力描述、标准化快照及统一适配器协议。
- 保留原始解析器，将 Codex、Claude、GLM 包装为适配器，避免重写全部读取逻辑。
- 将刷新、状态、通知接线迁移到注册表和账户集合；复用 `UsageLoader` 的独立刷新与取消语义。
- 将固定来源通知改为账户＋窗口标识，保持首次读取不误报、失败不冒充额度耗尽。
- 调整 Claude 查询优先级；有消耗的探测路径加入显式开关和说明。
- 迁移现有排序、GLM 配置和 Claude 缓存，保持已有账户可继续使用。

交付：基于通用接口运行的现有三个来源。

完成条件：新增来源无需继续往 AppDelegate 添加整套专用状态；旧账户、排序、缓存和通知均有对应迁移路径。

### P2：账户管理、认证与动态展示

工作：

- 增加统一连接设置：添加来源、命名账户、选择区域、登录／配置、启停、删除、排序和刷新状态。
- 按账户 ID 保存独立的钥匙串凭据；更换凭据时取消旧请求并清空不属于新账户的快照。
- 自动发现可接入的本机工具与登录入口，由用户选择添加；浏览器来源按需要提供登录或 Cookie 配置。
- 改造刘海和无刘海胶囊，从固定三行改为最多三个可选常驻项；展开面板显示全部已启用连接。
- 按能力选择指标：百分比／重置、金额、Token 或费用；没有总量时展示实际数值。
- 保留现有紧凑布局、拖动排序、刷新状态和旧数据提示，扩充账户辨识信息。

交付：可管理任意数量连接的设置与展示流程。

完成条件：两个同来源账户不会覆盖凭据或快照；第四个连接可在展开面板出现；固定项数量及选择规则一致。

多账户限制：某个 CLI 只能读取当前登录账户时，明确标记“当前 CLI 账户”。额外账户通过该来源支持的独立 profile 或账户认证实现，不通过改写外部工具默认登录态来模拟多账户。

### P3：分批增加内置适配器

分批是实现与审查顺序，不代表只交付第一批。每家均按实际能力接入，不以只有名称和图标的条目计作支持。

| 批次 | 覆盖候选 | 主要交付 |
| --- | --- | --- |
| A：套餐与余额 | Kimi Code、MiniMax 国内／国际、GLM／Z.ai、DeepSeek、Moonshot 国内／国际、OpenRouter、SiliconFlow | 扩展套餐窗口、区域认证、账户／Key 余额 |
| B：工具订阅 | GitHub Copilot、Gemini、Antigravity、Cursor、Windsurf、Kiro、Factory／Droid、Warp | 登录态读取、套餐额度、账期与可用的费用信息 |
| C：其余套餐和余额 | 阿里 Coding Plan、火山 Coding／Agent Plan、StepFun、腾讯企业 Token Plan、OpenCode Go、Command Code、ZenMux、Novita、AiHubMix | 不同认证、团队套餐、更多余额与窗口 |
| D：额外指标与已有工具 | OpenAI API 组织用量／费用、Claude 组织费用；Magpie／CC Switch 可用的数据连接 | 需要额外权限的账单能力，以及已有采集结果复用 |

执行要求：

- 每家交付配置字段、凭据处理、请求与解析、标准化映射、错误提示和支持说明。
- API Key 余额与订阅套餐使用不同产品标识；例如 Moonshot API 与 Kimi Code 不合并为一项能力。
- 管理级 Key、平台会话、云账号权限等作为额外能力前提展示；普通 API Key 不承诺具备相同数据权限。
- 对只有源码读取路径、尚无真实账户核验的适配器标注验证状态；接口受限时记录具体阻碍，不用估算余额替代查询。
- 优先复用已有工具的明确数据接口。无稳定接口时采用用户指定的只读导出／本地数据契约，并避免读取业务内容和改写其他工具配置。

交付：逐项更新的内置支持矩阵与适配器。

完成条件：每项“支持”都有可执行的读取路径、明确认证条件和实际指标；已验证与未验证分开记录。

### P4：自定义来源表单与字段映射

工作：

- 支持名称、查询 URL、GET／POST、请求头、请求体和独立认证字段。
- 支持对象路径、数组索引／映射、数值转换、缩放系数、额度方向、单位、周期和时间格式配置。
- 支持同一响应映射多条指标，覆盖额度、余额、Token 和费用；只做声明式转换，不执行任意代码。
- 提供用户主动触发的连接预览，展示脱敏响应和映射结果。
- 提供通用 JSON、New API／One API、Sub2API 等可核实的内置模板。
- 模板导入／导出排除密钥、Cookie 和其他敏感认证字段；凭据绑定配置的目标来源，重定向不转发敏感认证信息。

交付：无需改 Swift 源码即可添加 HTTP＋JSON 来源的完整流程。

完成条件：用户可从添加、配置、预览到启用完成操作；导出模板可复用且不包含凭据。

### P5：Token 采集、本地历史与统计窗口

工作：

- 先支持 Codex、Claude、Gemini、OpenCode 日志，再按明确格式扩展 Pi、Kimi Code、MiniMax Code、Antigravity 等来源。
- 只提取用量相关记录，不保存提示词、回复、代码和完整会话。
- 使用版本化本地数据库存储用量事件、历史读数与导入游标；支持增量读取、文件轮换及重新启动后的去重。
- 区分增量事件和累计快照，避免每次刷新重复累计；已有工具数据与直接日志重叠时按可靠 ID 去重，无法证明同一性的记录分开展示或选定统计来源。
- 定价来源支持更新及用户覆盖，保留所用模型、价格版本和估算标记；缺失价格显示未知。
- 实现今天／7 天／30 天筛选、工具／账户／模型分组及趋势；明确本地时区和时间范围。
- 提供历史清理入口；采集覆盖不完整、无法归属账户、不同币种等情况在汇总中明确表达。

交付：独立轻量统计窗口、增量日志采集器及本地历史存储。

完成条件：重复刷新／重复扫描不重复记账；估算费用与服务商费用不重复相加；能追溯统计的来源与覆盖范围。

## 6. 验证计划与执行约束

功能改造阶段仅进行源码层面的人工核对；随后在用户明确要求下完成构建、签名与本机安装校验。单元测试、lint、单独类型检查、逐项真实账户核验或浏览器视觉测试均未运行。新增测试源码不能算作测试通过。

后续仅在用户明确要求验证时，执行相应检查：

- 自动检查候选：`swift test`、`./build-app.sh`；覆盖解析、迁移、账户隔离、取消请求、字段映射、统计去重、费用与时间边界。
- 真实账户核验：按来源分别验证认证、响应口径、账户身份、重置时间和失败恢复；只使用用户已配置并授权使用的连接。
- 原生界面核验：按授权检查刘海／无刘海、多账户、排序、设置、映射和统计窗口。
- 外部动作：当前不提交、不 push、不发布、不替换已安装应用；这些动作按之后的具体指令执行。

区分“已实现”“自动检查通过”“真实账户核验通过”和“界面验收通过”，不将任何一个状态替代其他状态。
